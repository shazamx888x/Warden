## The problem

Peoplecraft HR runs the HR Assistant, a chatbot over HR files with an agent that can act. It shipped with no security review. Three things are wrong:

- Outsiders can talk to the model. Candidate CVs and web pages are read into the prompt, so a hidden instruction is an instruction to the app.
- Retrieval ignores who is asking. Everyone gets the same answers, so the assistant is a way round the HR system's permissions.
- The agent can act, and nothing checks the action. An injected instruction can email a file out or change pay.

Warden is the gateway in front of that app. The app is not changed.

## The eight controls

| id | control | what it does |
|---|---|---|
| W1 | `fast_rules` | Cheap pattern rules on every input and document |
| W2 | `injection_classifier` | Prompt Guard: score text for injection intent |
| W3 | `harm_check` | Llama Guard: classify harmful requests and answers |
| W4 | `ingest_scan` | Scan documents and mask PII BEFORE indexing |
| W5 | `permission_retrieval` | Only retrieve chunks the caller may read |
| W6 | `output_scan` | Catch cards, NI numbers, bank details, keys, beacons |
| W7 | `canary` | Detect a system prompt leak by its canary token |
| W8 | `tool_policy` | Allow, block or ask a human for every tool call |

Order is load bearing. Cheap checks run first. The controls that stop harm rather than flag it (W5 permission-aware retrieval, W8 the tool policy) run where they can actually intervene.

## Roles and permissions

| role | clearance summary |
|---|---|
| employee | own record and public policies only |
| line_manager | own team's payroll and contracts, plus public |
| hr_advisor | all contracts and CVs, plus public |
| payroll_officer | all payroll and contracts, plus public |
| recruiter | CVs only, plus public |

Access is by group, deny by default. Trust is a separate idea from sensitivity: a CV is low sensitivity and completely untrusted.

## The agent's tools

| tool | changes the world? | policy |
|---|---|---|
| lookup_employee | no | any signed-in staff |
| search_web | no | any signed-in staff; result is untrusted |
| email_document | yes | company domain only, else block |
| raise_payroll_change | yes | payroll role; ask a human over GBP 500, block over GBP 10,000 |

## Thresholds

| setting | value |
|---|---|
| injection score to block (W2) | 0.8 |
